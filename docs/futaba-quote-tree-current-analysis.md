# ふたば引用ツリー 現状分析

## 処理の流れ

1. `FutabaThreadClient` がレス番号、本文、引用行、引用深度、解析前の引用文、添付URLを抽出する。
2. `futaba-quotes.js` が引用元を過去レスと照合する。
3. `getPostReferences()` が解決済みの親レス番号をツリー描画処理へ渡す。
4. `buildReverseIndexFrom()` などが親子関係と返信件数を構築する。
5. `tree` は元レスを残したまま子レスを親の下へ埋め込み、`dedupTree2` は重複表示を避けて1箇所へ配置する。

## 引用元の解決

- `>No.123` は明示的なレス番号参照として扱う。
- 添付ファイル名は過去レスの添付URLと照合する。
- その他の引用文は過去レス本文との一致・部分一致で候補を求める。
- 結果は `resolved`、`ambiguous`、`unresolved` の3状態で管理する。
- 曖昧または未解決の場合は誤った親レスへ接続しない。

## 引用表示

- `flat` では本文を通常どおり表示する。
- ツリーに埋め込まれた子レスで引用元が解決済みの場合、引用本文を `>>親レス番号` リンクへ置き換える。
- ふたば固有の `>No.123` も通常のレスアンカーとして扱う。
- 引用リンクのポップアップには親レスのヘッダと、子レスが実際に引用した原文部分だけを表示する。
- ポップアップの引用文は、深度から `>` を再構成せず、解析前の `OriginalText` を使用する。
- 通常本文に元からある `>>123` は、従来どおり親レス全体をポップアップ表示する。

## 現状の制限

- 明示番号のない引用文で同じ文章が複数レスに存在する場合、親を一意に決められない。
- 引用文へのツッコミなど、行頭の `>` が引用本文かレス本文かを意味だけで完全に判定することはできない。
- `tree` モードでは元レスが末尾にも残るため、同じレスについて通常表示と埋め込み表示の見え方が異なる場合がある。
- 実スレ上の最終的な表示・ホバーポップアップ動作はユーザー確認が必要。
