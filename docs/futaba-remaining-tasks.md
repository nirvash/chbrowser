# Lunaへの残課題対応指示（性能修正後）

## 開始指示

この指示書を渡されたLunaは、残課題の実装を開始してよい。AGENTS.mdを読み、現在のブランチと未commit変更を確認する。各段階の終了時に自己レビューと進捗報告を行い、次へ進む。仕様変更が必要な場合だけユーザーへ確認する。

対象はふたばの引用解析・2モードのツリー表示・引用プレビュー。以下の順番で対応し、最後に通常出力のDebug版をビルドする。commit・push・merge・releaseは行わず、ユーザー動作確認待ちで終了する。

## 完了済みの性能修正を維持する

- 取得・ディスク復元時にC#で解析し、元HTMLハッシュ＋ページURL＋Versionで永続キャッシュを検証する構成へ変更済み。
- 本番の親解決は `Services/Api/FutabaQuoteAnalyzer.cs`。`Resources/futaba-quotes.js` は旧ペイロード用fallback。**JSだけ直して完了にしない。**
- C#パーサ・親解決規則・キャッシュ構造を変更したら `FutabaAnalysisCache.Version` を上げる（今回の残課題では必要）。古いキャッシュから新しい解析結果へ移行するテストを追加する。
- 描画中に全件解析・全件署名計算を復活させない。1001レスでC#解析保存64ms、実アプリ初回描画172msが前段の実測。数字だけでなく呼出し回数・処理量の回帰を防ぐ。
- `b558b62` のスクロール復元・新着境界と初回ready再同期は保護する。
- 詳細は [性能修正の設計と検証](futaba-analysis-performance.md)。[旧commitレビュー](futaba-quote-tree-review-fixes.md)は原因の資料として読み、完了済み性能修正をやり直さない。

## 維持する表示仕様

- 重複あり=`tree`、重複なし=`dedupTree2`。旧`dedupTree`はUI非到達。新しいモードは増やさない。
- 引用省略は引用元レス番号リンクへの置換。ホバーでは子が実際に引用した部分を表示する。detailsへの変更は禁止。
- 通常のレス番号リンクのポップアップは対象レス全文。
- 引用と返答の交互構造は全文を残す。曖昧な引用元を直近投稿へ決め打ちしない。
- `Body` は原文を保持。NG・検索・コピー・AI向けの内容を引用省略で変えない。

## 1. 引用深さの解析修正（P1）

対象: `FutabaThreadClient.BuildQuoteInfo` / `AddQuoteLine` / `QuoteTagRe`。

- `<br>`を改行として残して判定する。閉じ`</font>`/`</span>`は属性を要求せず正しく追跡し、非引用行に引用深さを漏らさない。
- 行頭の引用記号の深さを優先する。`>No.X`の参照種別とquoteDepthを分離し、勝手に0へ変更しない。
- 実サンプル1432673776の通常返答2行、1432664676のURL行はdepth=0。`>No.X`は1、`>>No.X`は2。
- 実C# Parseの回帰テストを先に追加し、本文→引用→本文、複数行を包む引用font、通常fontの入れ子、空行、エンティティを検証する。

## 2. 直接親と引用文脈の解決（P1）

対象: C# `FutabaQuoteAnalyzer`、JS fallback、必要なら結果record。

- 深さ2以上のNo./画像名は継承された文脈で、直接親に加えない。
- 実投稿1432667966の親は1432667645のみ。祖先1432667536を追加して複数親扱いにしない。
- 引用記号をちょうど1段除いた行列を、候補投稿の引用深さ付き本文へ照合する。各行の候補をunionするだけでは不十分。
- 同じ返答をした2投稿を、引用文脈で一意に区別できる例を追加する。文脈も同じなら未解決のまま残す。
- 引用行と対応親の情報を返し、表示とプレビューが同じ根拠を使えるようにする。本文全走査を毎投稿繰り返す設計へ戻さない。
- 旅行の実チェーン `1432664524 → 1432664980 → 1432665033 → 1432665126` と別分岐をテストする。架空の親は作らない。
- 本番C#とJS fallbackを同じfixtureで検証し、新キャッシュVersionへの移行も確認する。

## 3. 引用表示・プレビュー（P1/P2）

対象: `thread.js` の `buildFutabaDisplayBody` / `postDataFor` / `openQuotePreviewPopup`。

- 返答の後に引用が再出現する投稿はリンク置換しない。NISA例1432662652の引用2行＋返答2行をすべて表示する。
- 表示コンテキストを実際に使い、親が表示されない状態で引用だけを消さない。既存の親欠落ガードは維持し、フィルタによる非表示も検証する。
- 通常ポップアップは全文表示、置換リンクのプレビューはそのリンクに対応する引用部分。複数親すべてに同じ引用ブロックを渡さない。
- ポップアップには正本IDを付けない（`omitId=true`）。同じ投稿のポップアップを複数開いても`#r番号`は本文の正本1件のみ。
- ヘッダを作るためだけに本文のメディア抽出等を繰り返さない。カスタムpostテンプレートを壊す必須DOMは増やさない。

## 4. 重複ありツリーの多段表示（P2）

- 現状は親の正本だけに返信複製を追加し、親複製に子孫が付かない。ふたばのreverse複製にも必要な子孫を描画する。
- forward埋め込みを循環させない。深さ・複製数に上限を設け、正本と続きへの参照を残す。
- 両モードで旅行の4投稿・3本の親子関係をDOMで確認する。初回、新着、分割バッチ、resync、モード切替を検証する。
- `dedupTree2`の既読部分の凍結、新着末尾表示、ID一意性、既読スクロール復元を維持する。5ch側の既存表示を無断で変えない。

## 別枠の未解決事項

`ApplyFetchDelta`は件数を境界に追加分を表示するため、既存投稿の編集・削除・添付差替えが、取得後すぐ既存DOMへ反映されない。元HTMLと解析キャッシュの更新は対応済み。これは今回の1〜4と混ぜず、必要なら別タスクとして、投稿番号による差分・NG・既読位置・新着セクション保持の設計から提示する。
