# ふたば取得・解析キャッシュの性能修正

2026-09-05。株スレ表示停止の性能問題を修正。引用元を選ぶ規則や省略UIの改善は別タスク。

## 処理の流れ

1. `DatClient` のネットワーク取得・ディスク復元は、どちらも `FutabaAnalysisCache.LoadAsync` を通す。
2. 元HTMLのSHA-256、ページURL、解析バージョンが一致すれば、解析済みPostと引用解決結果を再利用する。
3. 未作成・不一致・破損時は、ワーカースレッドでHTMLを解析し、`FutabaQuoteAnalyzer` で引用元を解決する。
4. 結果を `<threadKey>.futaba.htm.analysis.json` に保存。一時ファイルから置換し、不完全な書き込みを読み手に見せない。保存失敗時も解析結果を表示へ返す。
5. 画面には `Post.FutabaQuoteResolution` を渡す。親取得・本文表示・返信数更新はこれを読むだけで全件解析しない。
6. 古いペイロード・プレビューだけはJS解決器を使うが、受信バッチごとに一度、描画前に準備する。投稿ごとの署名計算・全件再解析は禁止。

元HTMLが正本。解析キャッシュは削除しても次回復元できる。ログ削除時にはsidecarも削除する。件数が同じでも本文・添付が変わればHTMLハッシュで失効する。同じ名前の板でもホストが違えばページURLで区別する。

## 解析器の負荷

従来は投稿追加のたびに全文の署名を作り、全投稿×全引用×過去本文を再走査していた。
新しいC#解析器では正規化本文を一度作り、4文字gramの索引から部分一致の候補を絞る。添付URLもbasenameへ一度変換して保持する。曖昧候補から恣意的に親を選ばない。

UIでNGにより親が無い場合には、永続化された参照だけで引用を消さない。元引用を表示する。

## 今後の引用ロジック修正時

- 本番の解析結果の生成元は **`Services/Api/FutabaQuoteAnalyzer.cs`**。`futaba-quotes.js` だけを直しても新しい本番データには反映されない。
- C#の本文解析、引用判定、キャッシュ構造を変えたら **`FutabaAnalysisCache.Version` を上げる**。既存sidecarは次のロードで再生成される。
- JSの旧ペイロード用fallbackも同じ意味に合わせて保守する。
- 現時点では1001投稿について、変更前のJS解決器とC#解決器のstate/parentNumbers/ambiguousLinesが全件一致することを確認した。以前のレビューで指摘した文脈判定等の問題まで解決したという意味ではない。
- 既存のタブへの差分適用は従来の `ApplyFetchDelta` の件数境界処理。既存投稿の変更・削除を即座にDOMへ反映する仕様は別途検討が必要。元HTMLと永続解析キャッシュは取得ごとに更新される。

異なる段階・件数の計測であり、厳密な改善倍率として比較しない。UI値はJSの `appendPosts` 処理完了までで、画像全件ダウンロード時間を含まない。目視の最終判断はユーザー確認。

C#検証では実際のHTMLパーサ、部分一致・曖昧参照、画像所有者、ソース変更、ページ変更、バージョン変更、破損／不完全キャッシュ、保存失敗、キャンセル、同時書込みを確認。
Nodeでは5000投稿の解析済みペイロードが過去投稿走査や再解析を呼ばないこと、旧ペイロードの添付のみ更新、resync時の解決結果差替え、NG親欠落時の原文保持、5chの既存経路を確認。
